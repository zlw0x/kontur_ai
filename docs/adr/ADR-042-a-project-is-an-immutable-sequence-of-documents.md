# ADR-042: редактирование — последовательность неизменяемых CAD-IR

Статус: принято. Дата: 2026-11-18. Миграция: 0013_cad_projects.

## Решение

CAD-IR 1.15 остаётся единственным параметрическим источником модели.
`cad_projects` хранит владельца и номер текущей версии; `cad_project_versions`
хранит полный неизменяемый снимок CAD-IR, команду, идентификаторы задания и
заказа. Исходный документ — версия 1. Старые версии никогда не переписываются.
Восстановление создаёт новую версию и новую проверенную сборку.

Новая модель создаётся из готового заказа пользователя либо из ограниченного
шаблона открытого прямоугольного корпуса. Произвольный клиентский CAD-IR не
принимается: диагностический endpoint остаётся доступен только сотрудникам.

Правка не обращается к vision/LLM. Доверенный редактор меняет существующие
значения или добавляет типизированный круговой `cut.extrude`, затем заново
пропускает документ через канонический валидатор. Числовые поля и ограниченная
русская грамматика команд используют один редактор. Неоднозначные и неполные
команды отклоняются, размеры не угадываются. Схема CAD-IR не меняется.

Каждая новая версия использует существующий `BUILD_CAD`: тот же worker,
build123d, STEP/STL, проверка повторно открытых файлов. В API не импортируется
CAD-движок. Завершение проектной сборки без `VALIDATION_REPORT.valid == true`
отклоняется. Политика модерации существующих заказов сохраняется; для полностью
автоматического локального приёмочного прогона используется
`AUTOMATIC_ACCEPTANCE=true`.

Снимок сохраняется до отправки в очередь. Его UUID задания и заказа повторно
используются при повторной отправке; сбой явно виден как `DISPATCH_PENDING`.
`POST /projects/{id}/retry-build` и повтор исходной правки восстанавливают
отправку. Это небольшой долговечный журнал отправки, без новой службы.

`expected_revision` атомарно сравнивается с текущей версией SQL UPDATE.
`action_id` уникален в проекте: повтор той же операции возвращает сохранённый
результат, повтор UUID с другим содержимым даёт 409. Параллельная устаревшая
правка не перезаписывает проект. Ошибка геометрии оставляет неуспешную версию в
истории; предыдущую проверенную модель можно восстановить.

Владение и CSRF используют существующие session/cookie-проверки. Чужой проект,
история и CAD-IR отвечают тем же 404, что отсутствующий. CAD-IR скачивается
владельцем как редактируемый проект; STEP и STL остаются файлами геометрии.

## Размеры и независимая проверка

Контрольные габариты обновляются только по явной связи оси с параметром
первого прямоугольного выдавливания XY: ширина→X, длина→Y, глубина→Z.
Исходное контрольное значение должно совпадать с исходным размером. Это
перенос явно изменённого пользователем размера, а не измерение ожидаемого
результата по только что построенной геометрии. Остальные ожидания сохраняются
и могут отклонить неподдерживаемое сочетание изменений.

Новое отверстие обязано целиком лежать внутри прямоугольного контура;
контрольное число сквозных отверстий увеличивается на одно. Совпадающее с
существующим отверстием вычитание не увеличит фактическое число отверстий и
будет отклонено независимым verifier.

Лимиты новых заданий применяются и к правкам. Завершённые задания больше не
считаются занятыми слотами: статус заказа может оставаться `WAITING`, потому
что прогресс вычисляется по заданию. Суточный лимит остаётся в силе.

## Границы этого этапа

Текстовый ввод — документированная ограниченная грамматика, не универсальный
чат с CAD. Автоматическое связывание всех геометрических ожиданий произвольного
документа, перенос отверстий по поверхности, подсветка граней, восстановление
проекта из загруженного файла, оплата и новая обработка фото не входят в этап.
Полное дерево параметров FreeCAD не обещается.

PostgreSQL остаётся производственной БД; SQLite используется в локальных
проверках. Платёжные права на скачивание появятся отдельным этапом.
