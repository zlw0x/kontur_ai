# POSTMVP-013/014: the golden corpus and the reliability gate — acceptance

**Date:** 2026-07-31 · **Result:** PASS. Every operation the corpus covers is promoted
from `experimental` to `beta`; `feature.chamfer.asymmetric` is not, and the reason is
below.

Every milestone before this was accepted on one fixture and a handful of refusals. That
is enough to show an operation works; it is not enough to let the API schedule a job that
needs it. This is the body of evidence, and the gate that runs it.

## What the corpus is

`packages/build123d-adapter/tests/golden_corpus.py` — **42 positive cases and 16 negative
ones**, generated by substituting numbers into document shapes.

| what it covers | cases |
|---|---|
| plain plates, three sizes | 3 |
| discs, polygons (3, 6, 12 sides), slots | 7 |
| a stadium spelled out as lines and arcs | 2 |
| round holes as islands and as cuts, 1/2/4 of each | 6 |
| a blind pocket | 1 |
| openings that are rectangles, slots, hexagons | 3 |
| bosses on a datum plane, and one on a selected face | 3 |
| revolves at 360°, 180°, 90° | 3 |
| corner fillets R3 and R8 | 2 |
| bore chamfers 2 mm and 4 mm | 2 |
| patterns: linear ×2, circular ×2, a grid, a mirror | 6 |
| two separate bodies, union, subtract, intersect | 4 |

Three rules make it a corpus rather than a large test.

**Every expected number is closed-form.** A plate is `w × h × t`; a hole removes `π r² t`;
a regular n-gon of circumradius R has area `½ n R² sin(2π/n)`; a slot is `π r² + 2 r L`; a
45° chamfer of `d` on a bore of radius R removes `π(R d² + d³/3)`; a partial revolve
removes the fraction of a turn it did not sweep. None of it is read back from the engine,
so a case cannot pass by the engine agreeing with itself — ADR-018's argument about
expectations, applied to the corpus that checks them.

**The generator is dumb on purpose.** It does no geometry, so there is nothing in it that
could compensate for a mistake in the engine.

**A negative case names the code it must fail with.** "Refused" is not a result: a repair
loop reacts to the code.

## What the gate asserts

`test_corpus.py`, 70 tests, in the ordinary suite:

1. every positive case **builds and verifies** — the files are reopened and every
   expectation the document carries is checked;
2. every positive case **measures the arithmetic**, to 1e-3 mm³, and has the body count it
   declares;
3. every negative case is **refused with the code it named**, and leaves nothing on disk;
4. seven cases across the operations are built **twice** and compared byte for byte;
5. the corpus **covers every capability the engine declares** — a new operation without a
   case fails here rather than quietly leaving the corpus behind.

### Determinism, measured rather than assumed

```text
STL:  byte-identical across runs
STEP: identical except one line — FILE_NAME('Open CASCADE Shape Model','2026-07-31T18:05:35',…)
```

Exactly one line of 415 differs, and it is the timestamp OpenCascade writes into every
file. A gate that compared digests would be flaky; this one knows precisely which
byte-level difference is legitimate, and a test asserts that no other line moves.

## Three defects the corpus found

**An island lying wholly outside the profile was silently ignored.** The existing check
catches an island that swallows the profile or cuts it in two — those leave the wrong
number of regions. One that misses entirely leaves exactly one region of exactly the same
size, so the engine built a plate with no hole in it and reported success. Now
`SKETCH_ISLAND_OUTSIDE_PROFILE`, by comparing the area the island removed against nothing.

**The mesh-versus-solid comparison was too strict for the format it reads.** An STL stores
coordinates as 32-bit floats. A triangular plate's height is 20√3 = 34.641016151377546 mm,
which binary32 keeps as 34.64101791381836 — 1.76e-6 mm *larger*. The check allowed 1e-6 of
overshoot and called that a mesh describing a bigger part than the model. The allowance is
now two units in the last place of the largest extent, named and explained.

**A kept overlapping tool is not one manifold, and that is the right answer.** Subtracting
a tool and keeping it always leaves two bodies sharing the face the cut was made on, and
the manifold check refuses it: five edges with four incident triangles instead of two. The
case is exercised by a test of its own rather than being admitted to the corpus, because
the alternative was weakening a check that would then be blind to every torn mesh.

## The promotion

| status | keys |
|---|---|
| `beta` | 32, including revolve, both blends, all three patterns, mirror, named bodies, all three booleans, convexity, `validate.surface_face_count` |
| `experimental` | 1 — `feature.chamfer.asymmetric` |

`experimental` means the API will not lease a job that needs the capability
(`LEASABLE_CAPABILITY_STATUSES`), so this promotion is what makes the operations reachable
through the manual API at all.

**Why the asymmetric chamfer is not promoted.** Which face the first distance is measured
from is the entire content of the operation, and the corpus does not vary it — the
blended-bracket fixture exercises it once. An operation does not earn a promotion because
its neighbours did.

## What this is *not*

**It is not Gate P2.** The roadmap asks for 100 golden models across 30 part types and 99%
deterministic build success on a synthetic corpus. Forty-two cases across fifteen part
shapes is a body of evidence, not that gate, and nothing here is declared `stable`.

**It does not exercise the worker's process handling.** "100 consecutive end-to-end runs
without a process leak" is about the worker starting containers, not about the engine
building documents. It belongs with the deployment run.

**Coverage is by operation, not by drawing.** Every case is a document written by the
generator. What a drawing agent can produce off a scan is still narrower, and widening it
is a vision problem.
